# SleepCP — patient-adaptive conformal prediction for sleep staging

Code and results for

> **Patient-adaptive conformal prediction sets for reliable single-channel EEG
> sleep staging**

The paper's claim is that the marginal coverage guarantee of split conformal
prediction is not the guarantee a clinician needs for sleep staging: a stager
can hit 90% coverage over epochs while nearly half its patients fall below nominal.
The repository contains the five-class Sleep-EDF experiments, every table and
figure in the manuscript, and the code that regenerates them.

## Headline results (Sleep-EDF-20, 20 subjects, α = 0.1)

| | Coverage | Worst patient | Per-patient SD | Set size |
|---|---|---|---|---|
| Pooled APS | 0.898 | 0.774 | 0.051 | 2.54 |
| Mondrian (per class) | 0.896 | 0.787 | 0.048 | 2.29 |
| Per-patient ACI (APS) | 0.904 | 0.886 | 0.012 | 2.49 |
| Pooled deficit | 0.889 | 0.792 | 0.045 | 1.53 |
| Deficit, per stage | 0.903 | 0.787 | 0.046 | 1.74 |
| Per-patient ACI (deficit) | 0.898 | 0.872 | 0.010 | 1.58 |

On the 78-subject cohort (seed 0, ten runs) the ordering is unchanged and the
pooled-to-per-patient gap is larger: worst-patient coverage moves from 0.641
to 0.879 under ACI, and the per-patient SD from 0.067 to 0.016.

Three findings organise the paper:

1. **The marginal guarantee is not the patient guarantee.** Per-patient
   statistics are computable only under a subject-wise split; the common
   random-epoch split reports exactly nominal coverage and no patient-level
   decomposition at all.
2. **Score smoothing is the largest efficiency lever.** Scoring the
   forward–backward posterior deficit instead of raw-softmax APS cuts set size
   by about two fifths at equal coverage and raises adjacent-set Jaccard
   consistency from 0.68 to 0.94. The gain is uneven by stage (N1 coverage
   falls); thresholding the same score per stage restores every stage to
   nominal at 1.74 labels, still well below APS at 2.54.
3. **Per-patient adaptation narrows the spread.** One ACI stream per patient
   lifts the worst patient from 0.774 to 0.886 and shrinks the per-patient SD
   from 0.051 to 0.012; the distance of a patient's coverage from nominal falls
   for 19 of 20 patients (Wilcoxon signed-rank p = 1e-5).

The dynamic-programming sequence constructors (SeqCP-Margin, SeqCP-Block) are
reported as a negative result with proofs: at β = 0 the margin constructor is
exactly per-epoch CP on the deficit score, at β ≥ 0.5 the block projection is
vacuously the full label set.

## Repository layout

```
src/sleepcp/        conformal primitives, HMM smoothing, DP constructors,
                    models, metrics
scripts/            data preparation, training, every analysis, aggregation,
                    LaTeX tables, figures
results/            per-run JSON (one directory per model/fold/seed) and
                    aggregated summaries; the JSON is released so every
                    number in the paper can be checked without retraining
paper/              elsarticle manuscript, figures, and EXPERIMENTS.md
                    (protocol and per-table provenance)
tests/              unit tests, including the brute-force DP check
```

`data/` and `logs/` are in `.gitignore`: the recordings are third-party data
and the logs are transient. Inside `results/` only the JSON is versioned; the
probability arrays (`.npz`) and checkpoints (`.pt`) are large and are
regenerated by the commands below. The released JSON under `results/main`,
`results/se78`, `results/cross` and `results/schedule` is what
`make_tables.py` and `make_figures.py` read.

## Environment

The experiments use an isolated conda environment (Python 3.11.18, PyTorch
2.9.1+cu128, NumPy 2.4.6, SciPy 1.17.1, matplotlib 3.11.2). Nothing is
installed into the global environment.

```bash
conda create -n sleepcp python=3.11 -y
conda activate sleepcp
pip install -r requirements.txt
pip install -e .
python scripts/check_environment.py
```

`requirements-lock.txt` records the exact versions used for the reported runs.
The models are small (1,445 and 224,069 parameters); a single 8 GB GPU is
sufficient, and CPU is a viable fallback for EEGNet.

## Data

Sleep-EDF Expanded is open access (ODC-BY 1.0) from PhysioNet.

```bash
bash scripts/download_sleep_edf.sh 20      # Sleep-EDF-20 (SC400–SC419)
bash scripts/download_sleep_edf.sh 78      # extended cohort (SC400–SC482)
bash scripts/download_telemetry.sh         # telemetry cohort (ST700–ST721)
```

Preprocess each cohort (Fpz–Cz, 0.5–30 Hz, 30 s epochs, per-recording z-score,
crop to the scored sleep period plus 30 min of wake):

```bash
python scripts/prepare_sleep_edf.py \
  --data-dir data/sleep-edf/sleep-cassette \
  --out-dir data/processed/sleep-edf-20 --subset sleep-edf-20
python scripts/prepare_sleep_edf.py \
  --data-dir data/sleep-edf/sleep-cassette \
  --out-dir data/processed/sleep-edf-78 --subset sleep-edf-78
python scripts/prepare_sleep_edf.py \
  --data-dir data/sleep-edf/sleep-telemetry \
  --out-dir data/processed/sleep-telemetry --subset all
```

## Reproducing the paper

The training and conformal-analysis steps driven by `run_matrix.sh` are
resumable: anything whose output file already exists is skipped, so a run can
be interrupted and restarted.
`train_cross_cohort.py` is the exception --- it always retrains --- so run it
once into a fresh directory per seed. Training is seeded and cuDNN is pinned
to deterministic kernels (`sleepcp.training.set_seed`), so a repeated
`train_eegnet.py` invocation reproduces the test probabilities bit for bit;
this was checked by retraining fold 0 / seed 0 while the main matrix was
running on the same GPU and comparing arrays. `run_matrix.sh` takes a lock directory
inside its results root and refuses to start a second concurrent matrix over
the same root, because two processes would otherwise train the same run twice
and interleave their analyses.

```bash
# 1. Main matrix: 2 models x 5 folds x 3 seeds = 30 runs.
#    Each run trains, then runs the SACP, temporal, ACI, diagnostic,
#    guarantee-check and (fold 0, seed 0) input-corruption analyses.
DATA=data/processed/sleep-edf-20 ROOT=results/main \
  bash scripts/run_matrix.sh "eegnet sleepcnn" "0 1 2"

# 2. Aggregate per-run JSON into the summary tables.
python scripts/aggregate.py --root results/main --out results/main/summary

# 3. Paired per-patient tests quoted in Section 5.4.
python scripts/paired_tests.py --root results/main \
  --out results/main/summary/paired.json

# 3b. ACI step-schedule check: repeat per-patient ACI with the
#     theory-compliant schedule gamma0/(t+2)^0.6 on the same fitted models.
bash scripts/run_aci_schedule_check.sh results/main results/schedule/main

# 3c. Fixed-shrinkage-weight sweep and nominal-level sensitivity, on the
#     same fitted models (no retraining).
python scripts/sacp_fixed_lambda.py --root results/main   --out results/main/summary/sacp_fixed_lambda.json
python scripts/alpha_sweep.py --root results/main   --out results/main/summary/alpha_sweep.json

# 4. LaTeX tables and figures. The hypnogram panel needs per-epoch sets,
#    which the run JSON does not store; export them for one test subject:
python scripts/export_hypnogram.py \
  --cal results/main/eegnet/fold0_seed0/eegnet_fold0_seed0_cal.npz \
  --test results/main/eegnet/fold0_seed0/eegnet_fold0_seed0_test.npz \
  --aci-json results/main/eegnet/fold0_seed0/subject_aci.json \
  --subject SC409 --start 1015 --out paper/figures/hypnogram_SC409.npz
python scripts/make_tables.py --summary results/main/summary
  # reads results/se78/summary for the extended-cohort table; pass
  # --extended to point elsewhere
python scripts/make_figures.py --root results/main \
  --epoch-sets paper/figures/hypnogram_SC409.npz

# 5. Cross-cohort shift (cassette <-> telemetry), both backbones. The two
#    directions train on one cohort and calibrate on four held-out subjects
#    of that cohort, then test on the other cohort.
for model in eegnet sleepcnn; do
  python scripts/train_cross_cohort.py \
    --train-dir data/processed/sleep-edf-20 \
    --test-dir data/processed/sleep-telemetry \
    --out-dir results/cross/sc2st/$model/seed0 --model "$model" --seed 0 \
    --no-class-weights
  python scripts/train_cross_cohort.py \
    --train-dir data/processed/sleep-telemetry \
    --test-dir data/processed/sleep-edf-20 \
    --out-dir results/cross/st2sc/$model/seed0 --model "$model" --seed 0 \
    --no-class-weights
done
bash scripts/run_cross_matrix.sh "sc2st st2sc" "eegnet sleepcnn"

# 6. Extended 78-subject cohort.
DATA=data/processed/sleep-edf-78 ROOT=results/se78 \
  bash scripts/run_matrix.sh "eegnet sleepcnn" "0"
```

The corruption study and the input-shift runs are invoked from
`run_matrix.sh`; `scripts/run_followups.sh` chains steps 5 and 6 after the
main matrix, and the paired tests and table/figure generation that follow the
aggregation. Every calibrated analysis is deterministic given the stored
probabilities, which is why the JSON is released: the cohort-size sweep
(`scripts/run_cohort_size.py`, one call per run directory, then
`scripts/aggregate.py`) is the only analysis not launched from
`run_matrix.sh`; `scripts/run_cohort_size_all.sh` runs it over every run
directory under a results root. Compile the manuscript with
`latexmk -pdf main.tex` from `paper/tex`.

## Tests

```bash
pytest -q
```

The suite covers the split-conformal quantile, the score families, the HMM
forward–backward pass, and a brute-force check of the dynamic program against
enumeration of all $K^L$ paths for small blocks.
`scripts/benchmark_smoothing.py` reproduces the per-epoch inference cost
quoted in Section 5.2 on the machine at hand.

## Provenance of the results

`paper/EXPERIMENTS.md` documents the protocol, the exact hyperparameters, and
the analysis behind each table and figure, including the negative results
(SACP weight selection, SeqCP-Block) that the paper reports as such.
